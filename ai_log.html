Selected prompts and responses

“Can you implement the comparison so both traversals process exactly the same initialized matrix, print a checksum to catch accidental differences, and avoid letting compiler vectorization hide the memory-access pattern?”

It checked that both loop orders produced checksum 2097144125 and saved the rows in evidence/locality.csv. It advised describing the timing difference as specific to the machine and run conditions.

Prompt 3 / monitoring check

“I’m adding a small localhost page to show the machine context and the busiest processes while the benchmark runs. The page currently calls the process column ‘current CPU percentage’; does the ps %CPU field really mean an instantaneous reading?”

Response: The assistant checked the installed ps manual instead of assuming the label was correct. It found that %CPU is CPU time divided by elapsed process running time, not an instantaneous sample, and changed the dashboard wording to “ordered by ps %CPU.” The supporting excerpt is saved as evidence/ps_cpu_semantics.txt.

AI error, correction, and evidence

What the AI got wrong

The first dashboard draft described its process ranking as “ordered by current CPU %.” That wording implies an instantaneous CPU sample. The dashboard actually obtains this field from `ps %CPU`, whose documented meaning is CPU time divided by elapsed process running time; it is not an instantaneous reading.

Machine evidence that disproved it

During validation, the assistant checked the installed `ps` manual and saved the relevant output in `evidence/ps_cpu_semantics.txt`. The local manual states:

%cpu / %CPU: CPU utilization of the process ... Currently, it is the CPU time used divided by the time the process has been running (cputime/real-time ratio), expressed as a percentage.

The live output is independently reproducible with ps -eo pid,stat,comm,%cpu --sort=-%cpu; its captured rows and process states are in `evidence/process_snapshot.txt`. The assistant corrected the dashboard label to “ordered by ps %CPU.” It now names the source metric without claiming it is instantaneous. Recheck this command yourself during your demo.
